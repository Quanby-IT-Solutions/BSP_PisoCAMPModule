# AN-9 acceptance evidence

Date: 2026-09-03 (Asia/Manila)
Baseline: `d5af99e` (AN-8)
Ticket: AN-9 — Export reports to Excel, Word and PDF with generation metadata

## Result

All four AN-9 acceptance criteria are **PASS**, with one scope note on the BSP
template (AC4), stated below rather than left implied.

## What AN-9 adds

| Layer | Surface |
| --- | --- |
| Contract | `REPORT_EXPORT_FORMATS`, `ReportExportFormatSchema`, `ExportReportInputSchema` |
| Backend | `report-tables.ts` (a KPI becomes tables), `ReportExportService` (tables become files), `ReportExportController` — behind `reports.reports.export` |
| Web | An Excel / Word / PDF link per run, on the report and in the history |

Dependencies: **xlsx via `exceljs`, docx via `docx`, pdf via `pdfkit`** — all
pure JavaScript, so the backend image needs no native build step or headless
browser.

## The shape that keeps three formats honest

A report becomes **titled tables** first, then each format renders tables. One
flattener per KPI and three renderers, rather than a renderer per KPI per
format. Without that middle step every new KPI would be written three times and
the three formats would drift apart.

## AC1 — each format opens with the data and the metadata

**PASS**, proved by opening each file with a real reader for that format rather
than by checking a magic number: a file that is nominally a workbook but that
Excel refuses is not an export anybody can use.

- **Excel** — `exceljs` loads the produced workbook and reads named cells. The
  metadata is its own `Report` sheet (so a reader can sort or filter the figures
  without dragging the header into them), and each table is its own sheet.
  Asserted: report name, generation date, generated by, period with timezone,
  data source, parameters, and the header row and first data row of a figures
  sheet.
- **Word** — `jszip` opens the `.docx` package the way Word does and reads
  `word/document.xml`. Opening the package proves it is well-formed, not merely
  that bytes exist. Asserted: the same metadata and the figures.
- **PDF** — the stream declares `%PDF-1.x`, contains a catalog and a page
  object, and **ends with `%%EOF`**; a truncated render has the first and not
  the last.

Run against the live stack, one file of each format opened and read back:

```

=== XLSX ===  9,296 bytes
```

Every registered report exports — the spec loops the whole registry and checks
each produces a metadata sheet **and** at least one of figures, so a KPI that
forgot to say how it becomes a table fails rather than silently exporting a
cover page.

A **withheld** report exports its reason rather than blank figures: a blank
report would read as a period in which nothing happened.

## AC2 — an export is audited with its format and its user

**PASS.** One `report.export` entry per export, naming the actor, the run, the
format, the definition and the period. Exporting the same report in all three
formats writes **three** entries — three things left the building, not one.
Asserted, along with the case that an export of a run that does not exist
writes nothing.

## AC3 — 403 and an audit entry with `generate` but not `export`

**PASS**, on exactly the user the ticket names: a holder of
`reports.reports.generate` **without** `reports.reports.export` is refused with
403 and one `permission_denied` row naming `ReportExportController.download`.
A holder of the export permission passes. Generating a report and taking a copy
of it out of the building are different privileges, and the fixture proves the
second is enforced separately from the first.

The browser run adds the same refusal end to end, using the signed-in user's own
session against the endpoint directly — the link is not on their page at all, so
the refusal has to come from the server rather than from the UI.

## AC4 — the approved template layout

**PARTIAL, and called out rather than claimed.** No BSP report template artefact
exists in this repository, so there is nothing to map onto. What is implemented:
a single layout, stated once in `reportHeader`, carrying the six fields §4.2-K
enumerates in one order, with one heading colour across all three formats so
they read as one set of documents. Swapping in BSP's approved template is a
change to the three renderers and that one function — not a change to any KPI.

**Exact next action if the template is required before sign-off:** add the BSP
template file (or its specification) to the repository, and map `reportHeader`
and the renderers' fonts, margins and heading styles onto it.

## Browser validation

`an9-report-exports.authenticated.spec.ts` — **7 passed**. For each of the three
formats: the link downloads, the browser is told the filename
(`activity-<from>-to-<to>.<ext>` — a report, not a run identifier), the saved
file is over 1 KB and starts with that format's signature. Plus: each export
link is named for the report and period it will download, so three links called
"Excel", "Word" and "PDF" are not three identical links to a screen reader; the
link is keyboard-focusable at 44 px; and the endpoint refuses a user without the
permission.

Console, page errors, failed requests and error responses asserted clean. The
backend log shows no error-level line; the only 4xx are the deliberate denials
and the auth rate limit tripped by repeated e2e sign-ins.

## Notes

- **The download is a plain Nest route, not an oRPC handler** — the same shape
  the bundle resource route already uses. The body is a file; a JSON envelope
  around it would mean the browser could not simply save it.
- **The export renders the stored run**, never a fresh query: an export has to
  be the report it claims to be, not a re-run that may since have moved. This is
  why AN-8 stores the result.
- Scheduled email delivery is out of scope, as the ticket says.
